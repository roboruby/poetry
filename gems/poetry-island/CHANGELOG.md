# Changelog

## [0.1.14]

- The committed component registry carries the component's `content` fact (poetry-core 0.1.14): whether it renders its content block.
- The gem: `poetry_island`, a bounded client mount inside server-rendered HTML for a widget whose state lives on the client (an editor, a canvas, a map, a 3D scene). The block is the shell the page shows before the module mounts and whenever it cannot; `import:` names an importmap specifier whose module exports `mount(element, props)` and returns `{ unmount, update? }`; `props:` serializes to a JSON script the module mounts with; `mode: :fill` paints the shell's box and `mode: :flow` takes its place; `name:` renders a hidden input inside the island (`props.input`) so the island's state submits with the form. One Stimulus controller handles the Turbo lifecycle for every island: mount on connect, unmount on disconnect, a morph refresh keeps the island and hands it the server's new props through `update`, a cached snapshot's dead root is cleared, a preview shows the shell, and a failed import or mount leaves the shell and dispatches `poetry--island--island:error`. No framework and no bundler ship with the gem: a plain module, a vendored kernel or a bundle built once all mount the same way.
